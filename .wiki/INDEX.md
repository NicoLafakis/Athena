# Athena Wiki Index

[`AGENTS.md`](../AGENTS.md) at the repo root is the terse, imperative rule set for any
agent working in this repo, regardless of harness; `CLAUDE.md` is a five-line pointer to
it. This wiki is where the reasoning and design detail behind those rules live. The two
must not become duplicate copies of the same content: `AGENTS.md` states the rule and
links here for depth, this wiki explains it.

## Architecture

- [Blind-first Jarvis upgrade](features/blind-first-jarvis/00-overview.md) - Canonical Tier 3 package, now in implementation. Its shared semantic plane feeds deterministic attention, bounded experience guidance, accessible presentation, watchers, and an opt-in Windows voice path whose raw microphone-to-Realtime-to-Marin probe has passed. The [direct-harness voice specification](features/blind-first-jarvis/direct-harness-voice.md) is implemented as of 2026-08-13: the intermediate conductor/delegation bridge is deleted, so every spoken work turn is ordinary input to one Athena harness session, with voice-answered permissions that refuse same-turn/stale/unknown/ambiguous replies and never reach `allow-always`, a bounded `system` conversation item that tells the live model session a decision is outstanding without granting it any authority to answer, a persistent wake listener (single supervised process, C# event sink) that the probe now actually drives, socket reconnect and turn-ID idempotency, and a no-free-text lifecycle ledger that makes both NFR budgets measurable. One gate remains: the [live acceptance run](features/blind-first-jarvis/acceptance-runbook.md), which needs a microphone, a human listener, NVDA, and Narrator, and which produces the latency, cost, and wake false-positive numbers. Retention review and cross-platform support remain open separately.
- [Voice-addressable project switching](features/voice-project-switching/00-overview.md) - DESIGN, piece 1 in progress. Closes the gap between what `athena voice` does today and the hands-free goal: re-rooting the session at another project by voice, and seeing it in the Ink display. The finding that shapes the work: `HarnessSessionController` has exactly one caller (the voice branch) while the interactive TUI composes its own engine, bus, gate, and trace inline in `main()`, so both missing capabilities cross that seam and unifying it is the real cost. Records why `cwd` is `readonly` on purpose - a dozen construction-time consumers including trust, project settings, and the resource policy would silently point at the previous project - so switching rebuilds the controller rather than mutating the field. Also carries Nico's 2026-08-13 trust-roots decision and its two consequences: auto-granting capabilities removes the content-digest re-prompt on hook changes, and a trust root is a standing grant covering any repo that later appears under it.
- [Computer use](features/computer-use/00-overview.md) - DESIGN ONLY, nothing implemented and nothing approved to build. Scopes OpenAI's GA computer-use tool (`{type: 'computer'}` on `gpt-5.6` via the Responses API; the widely-cited `computer-use-preview` is the retired preview). The finding that shapes the work: OpenAI does not provide the computer, so the real cost is a Windows screen-capture and synthetic-input layer that does not exist yet and has to be probed on real hardware first. Architecture decision: computer use is a bounded actuator Athena invokes inside one tool call, never an agent that drives Athena - ADR 0003's shape reused, so the conductor deleted on 2026-08-13 is not rebuilt with hands. Also records the risk the no-prompt posture does not cover: the model acts on what it reads, making any page or document an instruction channel, which is why its deny list stays independent of the global setting.
- [TUI fullscreen row budget](architecture/tui-fullscreen-row-budget.md) - The load-bearing layout invariant behind `src/tui/App.tsx`: only the Transcript box clips, every other sibling is unclipped and must be explicitly budgeted or Ink/Yoga corrupts the frame. Precedence order, the popup reserve-exactly-what-you-render rule, and transcript scrolling.
- [Credential storage and the OS vault](architecture/credential-storage.md) - Resolution order (env, file, vault), plaintext vs. vault-backed states and how the user is told which, the cross-machine story, Windows interpreter selection, and the standing rule that optional hardening must never be a fatal boot precondition.
- [Permissions and project trust](architecture/permissions-trust.md) - `permissionMode` vs. the per-machine trust registry, the one-way trust bootstrap (explicitly trusted projects start in trusted mode; win32 lifts the sandbox to unrestricted because no backend exists), and which rails (deny rules, resource policy, hooks) never relax. Also the protected-paths fence: an unconditional, environment-derived WRITE-only fence over OS directories that no permission or sandbox mode bypasses, its segment-boundary normalization (short names, device prefixes, junctions, admin shares), and the plainly-stated limit that the shell-command scan is best effort while Windows ACLs remain the primary defense.
- [Athena's self-reflection journal](architecture/self-reflection-journal.md) - Append-only operational journal grounded in evidence: auto-captured trace entries plus a model-authored channel for predictions scored against outcomes. Entry taxonomy, the mechanical guard against subjective self-narration being retrieved as fact, storage and rotation, and a phased build order.
- [Conversational continuity across time and projects](features/conversational-continuity/00-overview.md) - Local source-linked episode catalog, safe all-project discovery, nested fork lineage, timezone-aware timeline/search/show, on-demand source-linked day/week/month/quarter/year rollups, repeated source-verified semantic candidate generation with explicit local review, and local four-layer ranking previews are implemented. Ranking, rollup views, and managed semantic reads suppress unavailable sources; unreviewed semantic states stay out of model-facing reads. Synthetic quality and 10k-episode/10k-session latency samples are recorded; live-history dogfood, forget/delete integration, and automatic answer-provider handoff remain unfinished.
- [Jev decision-model proposal](features/conversational-continuity/adr/0003-jev-decision-model.md) - Research-backed proposal for optional TypeSafe System One routing, local authority boundaries, staged evaluation, and its separate vendor-data/consent requirements. No adapter is implemented.
- [Continuity calibration snapshot](features/conversational-continuity/calibration.md) - Synthetic candidate-precision, relevance, correction, temporal, and 10,000-episode performance results, with the exact limits of what the local measurements cover.
- [Memory hygiene / anti-rot](architecture/memory-hygiene.md) - Local semantic-memory schema/store, explicit remember, source-verified candidate generation/review, correction, and supersession are implemented. Managed semantic reads verify live session sources and keep unreviewed states out of model tool results; citation verification for legacy free-text files, legacy free-text review, and source-session deletion hooks remain planned, distinct from the governed-learning claims pipeline.
- [Environment staleness detection](architecture/environment-staleness.md) - Four filesystem/git signals (`stale-build`, `stale-deps`, `branch-behind`, `uncommitted-work`) that catch a stale `dist/` or `node_modules` running against fresh source on a two-machine workflow. Zero-subprocess boot checks versus git-backed doctor-only checks, the shared `VAULT_SPAWN_TIMEOUT_MS` and null-on-timeout lesson, and why every check degrades to `unknown` rather than ever blocking boot.

## Findings (root cause analyses)

- [RCA 2026-07-27: DPAPI boot abort on PowerShell 5.1 and the credential re-auth loop](findings/RCA-2026-07-27-athena-dpapi-boot-abort-and-credential-reauth-loop.md) - Critical. Commit 621dda3 made vault migration a fatal boot precondition; the Windows DPAPI one-liner does not load System.Security, so PowerShell 5.1 fails and Athena exits 1 before reading the key that is already on disk. See [Credential storage and the OS vault](architecture/credential-storage.md) for the resulting design.
